Serial Debug Assistant

A browser-based tool for sending and receiving data over USB Serial or MQTT over WebSocket. It supports raw text/hex communication, Modbus RTU/ASCII master polling, and Modbus slave simulation.

Requirements

  • Browser: Google Chrome or Microsoft Edge version 89 or newer. Firefox does not support the Web Serial API.
  • Served from: http://localhost, http://127.0.0.1, or any https:// origin. Opening directly as a file:// URL will not work.
  • Quick start: Run python3 -m http.server 8080 in the project folder, then open http://localhost:8080.
  • Linux users: Your account must be in the dialout group (sudo usermod -aG dialout $USER, then log out and back in). Snap-packaged Chromium sandboxes Web Serial — install Chrome from the official .deb package instead.

The top bar controls how the app connects to a serial device. Settings are remembered across sessions.

Serial settings (Baud, Data, Parity, Stop) can be changed while the port is open. The same port is closed and reopened with the new settings automatically (no port picker), and a Port settings → 115200 8N1 line is added to the receive area.
If the settings don't match the device (e.g. port at 9600, device sending at 115200), the adapter reports framing/break/parity errors. The port stays open: the status bar shows ⚠ N line errors and the receive area shows a warning about every 3 s. Change the baud rate to fix it, and click the counter to reset it. The port closes only if the device is really gone (unplugged); after that, Open works again without replugging.
Phones and narrow windows: the layout stacks vertically and settings are tucked behind the sliders buttons: port settings in the top bar, receive options, poll/import options, and each command's configuration. A collapsed command shows only its name, Modbus result and Send. Without Web Serial (iOS, Firefox), the page still works in MQTT mode.
USB adapters on Android: Chrome on Android can't see USB serial adapters through Web Serial, so the page talks to them directly over WebUSB with built-in drivers: CDC-ACM (boards with native USB: STM32, RP2040, ESP32-S2/S3, Arduino Leonardo/Micro…), FTDI (FT232R, FT-X, FT232H, FT2232, FT4232), CH340/CH341, CP210x and PL2303. Plug the adapter in with an OTG cable, click Open and pick it from Chrome's USB list, then allow access.
  • Via (Android only, in port settings): USB adapter (default) uses these drivers; Bluetooth / system uses Web Serial for paired Bluetooth serial devices.
  • Ch appears for adapters with several ports (FT2232, FT4232, CP2105, composite CDC) and picks the port (A, B, …).
  • DTR and RTS are switched on when the port opens (many CDC devices only send while DTR is on) and off when it closes. Baud/parity changes are applied without closing the port.
  • FTDI adapters also report framing/parity/break errors to the line-error counter.
  • "Could not take over the USB adapter" means another app has it: close apps like Serial USB Terminal (and clear "Open by default" for the device in Android settings), then unplug and replug.

Appears below the connection bar when the MQTT checkbox is ticked. The app connects to an MQTT broker over WebSocket — it does not use a native TCP MQTT port.

Modbus over MQTT: the app encodes each frame as an uppercase ASCII-hex string before publishing (e.g. 010300000001840A), and expects responses in the same format. This is the standard used by many IoT gateways (e.g. Teltonika).

Modbus Master Mode

When the Modbus checkbox is ticked on a command row, additional controls appear for reading a register value from a slave device.

How Modbus polling works

  1. The Send (or Poll) button sends the framed request.
  2. The result field shows … (waiting).
  3. Incoming bytes are accumulated. A 200 ms silence timer triggers response parsing.
  4. If no bytes arrive within 4 seconds, the result shows No response.
  5. The CRC (RTU) or LRC (ASCII) is verified. Any mismatch shows an error.
  6. Bytes 3 … N-2 (RTU) or frame payload (ASCII) are passed to the type/size/order decoder.

Modbus Slave (MS) Mode

Tick the MS checkbox in the connection bar to switch the app into Modbus slave mode. In this mode:

  • The app listens for Modbus requests and responds automatically.
  • The Send panel and Poll button are disabled — you are not a master here.
  • All existing extension commands are cleared (the list format changes for slave use).
  • Works over both Serial and MQTT.
1 2 3 4 5 6 7
1Name — label for this register (optional). 2Pattern (purple input) — the request pattern this entry responds to, as a hex string: ADDR FC RRRR (slave address, function code, register address). Spaces are ignored. Examples:
01030000 — slave 01, FC03, register 0x0000
01 03 0001 — slave 01, FC03, register 0x0001
Multiple entries can share the same ADDR+FC but different register addresses — multi-register requests are assembled from all matching entries. 3Value — the numeric value to return when polled. Type a decimal or hex number here; it is encoded according to Type, Size, and Order before responding. Update this at any time — the slave always responds with the current value in the field. 4Hex checkbox — Hex ON = RTU (expects binary frames with CRC-16). Hex OFF = ASCII (expects :HH…LRC\r\n framing). Must match the master's mode. 5Type — data type of the value: Unsigned / Signed / Float / Double. 6Size (bits) — determines how many bytes the encoded value occupies (8/16/32/64). A 32-bit value spans 2 Modbus registers; 64-bit spans 4. 7Byte order — same ABCD/DCBA/CDAB/BADC choices as master mode, applied when encoding the response bytes.

Multi-register requests

If a master asks for qty=4 registers (0x0000–0x0003) and you have two slave entries — one at register 0x0000 (32-bit Float) and one at 0x0002 (32-bit Signed) — the app combines both into a single 8-byte response automatically. Registers that have no matching entry are filled with zeros.

Show TX in slave mode

Enable Show TX in the Receive panel to see both the incoming request (→) and the slave's reply (←) in the receive area.

Poll & Loop

Polling sends all extension commands one by one with a configurable delay between each.

  • Click Poll to start. It highlights and reads "Stop Poll".
  • For Modbus commands, the poller waits for the response (or 4 s timeout) before moving to the next command.
  • For non-Modbus commands, the inter-command delay is applied immediately after sending.
  • If Loop is unchecked, polling stops after one full pass. If checked, it repeats until you click Stop Poll.
  • Polling stops automatically if the connection drops.
  • Polling is disabled in MS (slave) mode.

Import / Export Commands

Commands can be saved to and loaded from a JSON file, allowing you to share configurations between computers or maintain different command sets per project.

Export

Click Export in the Extension Commands header. A file named serial_commands.json is downloaded.

Import

Click Import and select a previously exported .json file. The current command list is replaced by the file contents. Invalid fields are silently substituted with defaults.

JSON format

Each command is an object in the array:

{
  "name":         "Temperature",   // display label
  "value":        "01 03 00 00 00 02",  // hex PDU or text payload
  "isHex":        true,            // Hex checkbox state
  "appendNL":     false,           // +\r\n checkbox
  "modbus":       true,            // Modbus master mode
  "mbType":       "float",         // "unsigned"|"signed"|"float"|"double"
  "mbSize":       32,              // 8|16|32|64
  "mbOrder":      "ABCD",          // "ABCD"|"DCBA"|"CDAB"|"BADC"
  "graph":        false,           // whether to plot on graph
  "graphColor":   "hsl(210,70%,60%)", // series colour
  "slavePattern": "01030000"       // slave mode pattern (addr+fc+reg hex)
}

Graph

Tick the Graph checkbox on any Modbus master command. A separate graph window opens automatically and plots the decoded value over time.

Tips & Common Tasks

Sending AT commands

Leave Hex unchecked, tick +\r\n, type your command (e.g. AT+GMR), and click Send.

Sending raw hex bytes

Tick Hex in the Send panel, type hex pairs (e.g. A5 01 FF), click Send. Spaces are optional — the field formats them automatically.

Modbus RTU quick-start

  1. Add a command, name it (e.g. "Temperature").
  2. In the value field enter the PDU: 01 03 00 00 00 02 (slave 1, FC3, reg 0, qty 2).
  3. Tick Modbus, then tick Hex (= RTU mode).
  4. Set Type=Float, Size=32, Order=ABCD (adjust to match your device).
  5. Click Send — the result field will show the decoded value.

Modbus ASCII quick-start

Same as RTU but leave Hex unchecked. The app automatically wraps the PDU in :HH…LRC\r\n framing.

Clearing a retained MQTT message

  1. Connect to MQTT.
  2. Tick the Retain checkbox.
  3. Set the Pub topic to the exact topic that has the retained message.
  4. Send an empty message (leave the Send field blank and click Send). This publishes an empty retained payload, which clears the retained message on the broker.

Testing without hardware (loopback)

For serial: connect a USB-to-serial adapter and short the TX and RX pins together — everything you send will come back. For MQTT: set Pub and Sub to the same topic — you will receive your own messages back.

Settings that always reset on reload

  • MQTT checkbox — always starts unchecked (MQTT bar hidden).
  • Hex (Receive) — always starts unchecked.
  • Frame Break — always starts unchecked.
  • Time — always starts unchecked.

All other settings — baud, serial parameters, Hex (Send), +\r\n, Show TX, Modbus Slave (MS), MQTT credentials, topics, QoS, Retain, and Poll delay — are remembered in localStorage.

Log file format

Each line is prefixed with a [HH:MM:SS.mmm] timestamp. Frame breaks appear as a plain line break. Session start/end markers are written automatically.
